# 05.6 API & Integration Architecture

## REST

Versionada:
`/api/v1`

Recursos:
`/users /workspaces /institutions /connections /accounts /cards /invoices /transactions /categories /merchants /installments /recurring-expenses /goals /analytics /health /forecasts /insights /simulations /copilot /imports /subscriptions /usage`

## Métodos

GET / POST / PUT / PATCH / DELETE.

Ações de domínio podem usar:
`POST /resource/{id}/action`

## Paginação

MVP: offset.
`pageSize <= 100`.
Cursor quando justificado.

## DTOs

DTOs separados de entidades de domínio/JPA.

## Money

```json
{
  "amount": "123.45",
  "currency": "BRL"
}
```

## Datas

YYYY-MM-DD.

Timestamps:
ISO-8601 UTC.

## Erros

```json
{
  "code": "CREDIT_LIMIT_INVALID",
  "message": "...",
  "details": [],
  "traceId": "01J..."
}
```

Status esperados:
200, 201, 202, 204, 400, 401, 403, 404, 409, 422, 429, 500, 503.

## Idempotência

`Idempotency-Key` em:
- imports
- payments
- transactions
- contributions
- sync
- billing
- webhooks

Guardar request hash.

## Home

`GET /api/v1/home`

## Imports

Multipart + processamento assíncrono + 202 + status endpoint.

## Copilot

Conversations/messages e contexto opcional validado.

## Open Finance

`OpenFinancePort`.

## Billing

`BillingPort`.
Webhooks assinados e idempotentes.

## Integrações externas

Sempre com:
- timeout
- retry
- circuit breaker quando aplicável
- idempotência
- observabilidade
- validação
- rate limit

## OpenAPI

Documentação code-first e client tipado frontend preferencialmente gerado/revisado a partir do contrato.

## CORS

Restritivo.

## Princípio

> A API transporta intenções e dados; o domínio decide regras; integrações ficam isoladas; a IA interpreta contexto validado.
