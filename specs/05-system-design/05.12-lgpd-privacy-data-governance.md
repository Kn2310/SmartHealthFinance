# 05.12 LGPD / Privacy & Data Governance

## Princípios

Privacy by Design / Default.

- minimização
- finalidade
- transparência
- controle do usuário
- segurança
- rastreabilidade

Dados financeiros não são automaticamente “dados pessoais sensíveis” na definição legal da LGPD, mas são tratados internamente como dados de alto risco.

## Classificação

- Public
- Internal
- Personal
- Financial
- Highly Sensitive
- Derived
- AI Context

## Proibições

Não armazenar:
- CVV
- senha bancária
- senha Open Finance
- secrets/tokens em plaintext

## Criptografia

- TLS em trânsito
- encryption at rest
- application encryption para campos sensíveis
- KMS/secret manager

## Workspace isolation

Obrigatória em autorização e testes.

## Consent

Estados:
PENDING / ACTIVE / EXPIRED / REVOKED / FAILED

Revogação:
- interromper sincronizações futuras
- invalidar credenciais
- auditar evento

Exclusão histórica é fluxo separado.

## Direitos

Implementar quando aplicável:
- confirmação/acesso
- correção
- exclusão
- portabilidade
- informações sobre compartilhamento
- revogação
- revisão/explicação de decisões automatizadas quando aplicável

Exports:
- autenticados
- expiráveis
- auditados

## Deletion

Definir hard/soft delete por caso.
Dados derivados devem ser apagáveis/reconstruíveis.
Backups também contêm dados pessoais e devem entrar na política de retenção.

## IA

- contexto mínimo
- sem DB direto
- PII minimizada
- não usar dados para treinamento externo por padrão
- separar conversation memory de financial state

## Logs

Nunca incluir secrets ou dados financeiros desnecessários.

## Auditoria

Audit log separado de logs técnicos.

## Open Finance / AI / profiling

Avaliar PIA antes de produção quando aplicável.

## Incidentes

Ter processo de detecção, contenção, análise, comunicação e recuperação.

## Desenvolvimento

Usar dados sintéticos/anônimos.

## Princípio

> Dados financeiros pertencem ao usuário; o sistema possui a responsabilidade de tratá-los com finalidade, segurança, transparência e controle.
