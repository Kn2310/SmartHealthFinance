# 05.11 DevOps & Deployment

## Git

Source of truth.

Fluxo:
feature/fix/hotfix → PR → main → CI → staging → production

## Versionamento

SemVer + commit SHA/build metadata.
Preferir deploy por SHA/digest.

## CI Backend

- checkout
- JDK/cache
- compile
- unit
- architecture
- integration
- contract
- static analysis
- security
- package
- Docker
- scan
- push

## CI Frontend

- Node/install
- lint
- typecheck
- unit/component
- build
- security
- Docker
- scan
- push

## Docker

Multi-stage.

## Environments

- local
- CI
- staging
- production

Nunca compartilhar dados reais entre ambientes.

## MVP

Single VPS/cloud equivalent:
- reverse proxy
- frontend
- API
- workers
- PostgreSQL
- Redis
- RabbitMQ

Evolução:
single host → multiple app instances → managed DB → dedicated workers → orchestration.

Kubernetes somente quando justificado.

## Secrets

Secret manager/injection.
Nunca commit.

## Migrations

Flyway expand/contract.

Rollback da aplicação não significa rollback automático do banco.

## Deploy

Inicial:
rolling/recreate conforme ambiente.

Futuro:
blue/green/canary.

## Workers

Graceful shutdown.
Drain.
Retry.
Idempotency.
No message loss.

## Dados

Backups + PITR quando disponível.
Restore tests.

## Feature flags

Para rollout controlado.

## Production access

Restrito e auditado.

## Princípio

> Deploy deve ser uma consequência previsível de código aprovado, não um evento manual e arriscado.
