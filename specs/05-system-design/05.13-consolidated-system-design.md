# 05.13 System Design Consolidation — FINAL

Este documento consolida a arquitetura aprovada do Smart Health Finance e é a principal fonte de verdade arquitetural.

## 1. Visão executiva

O produto é um **Domain-Centric Modular Monolith** em Java/Spring Boot, com Next.js/TypeScript no frontend, PostgreSQL como source of truth, Redis para cache/controle temporário, RabbitMQ para processamento assíncrono e OpenTelemetry para observabilidade.

A arquitetura prioriza:
- integridade financeira
- isolamento por Workspace
- simplicidade
- evolução incremental
- explicabilidade
- segurança
- privacidade
- IA desacoplada da verdade financeira

## 5. Financial Core

Regras:
- Workspace é boundary
- fatos financeiros persistidos
- dinheiro em NUMERIC
- valores positivos + type
- transferências não são despesas
- refund rastreável
- installments ≠ recurring
- confirmed/imported/estimated/simulated separados
- transações críticas protegidas por transação DB
- idempotência
- auditabilidade

## 7. Health

- Spending

## 8. Forecast

Forecast é derivado, versionado e deve distinguir:
- fato
- estimativa
- simulação

Não apresentar previsão como certeza.

## 9. Insights

Qualidade considera:
- Impact
- Relevance
- Confidence

Exemplo ruim:
“Você gastou R$ 12,50 a mais em café.”

Exemplo contextual:
“Seus gastos com alimentação fora de casa aumentaram 32% neste mês, representando aproximadamente R$ 280 adicionais.”

Exemplo acionável:
“Se você reduzir aproximadamente R$ 200/mês nessa categoria, sua meta de reserva poderá ser atingida cerca de 2 meses antes.”

## 10. Copilot

IA nunca acessa DB diretamente.

```text
Question
→ Auth
→ Workspace Authorization
→ Rate Limit
→ Intent
→ Context Builder
→ Financial Queries
→ Deterministic Calculations
→ Validation
→ LLM
→ Structured Output Validation
→ Financial Claim Validation
→ Response
```

## 11. API

REST `/api/v1`.

DTOs separados do domínio/JPA.
Money com amount + currency.
Errors com stable code + traceId.
Idempotency-Key em operações críticas.
OpenAPI como contrato.

## 12. Open Finance

Abstração:
`OpenFinancePort`

Providers são adapters.
Consent lifecycle:
PENDING / ACTIVE / EXPIRED / REVOKED / FAILED.

Tokens/credenciais protegidos.

## 14. Async

RabbitMQ + Transactional Outbox.
At-least-once.
Consumers idempotentes.
DLQ para fluxos críticos.
Retry com backoff + jitter.

Analytics/Health/Forecast/Insights devem ser derivados em fan-out quando possível.

## 24. Regras de ouro

1. Financeiro determinístico.
2. IA interpreta, nunca inventa.
3. Workspace isolation sempre.
4. Dinheiro nunca usa float.
5. Eventos são fatos; commands são intenções.
6. At-least-once + idempotência.
7. PostgreSQL é source of truth.
8. Redis nunca é source of truth.
9. Read models são reconstruíveis.
10. Integrações ficam atrás de ports/adapters.
11. Privacidade desde o desenho.
12. Observabilidade faz parte da feature.
13. Testes financeiros são obrigatórios.
14. Não microservicizar prematuramente.
15. Não redesenhar o produto sem aprovação.
