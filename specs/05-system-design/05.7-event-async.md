# 05.7 Event & Async Architecture

## Broker

RabbitMQ.

## Síncrono x assíncrono

Síncrono:
- invariantes
- comandos que precisam de resposta imediata

Assíncrono:
- dados derivados
- analytics
- health
- forecast
- insights
- integrações
- imports
- AI pesada

## Domain Events x Integration Events

Command = intenção.
Event = fato ocorrido.

## Transactional Outbox

Obrigatório quando um fato persistido precisa gerar evento.

## Delivery

At-least-once.
Nunca assumir exactly-once.

Consumers devem ser idempotentes.

Para consumidores críticos:
Inbox / `processed_events`.

## Envelope

```json
{
```

## Naming

`resource.action`

Mudanças incompatíveis criam nova versão.

## Workers

- analytics
- health
- forecast
- insights
- AI
- import
- Open Finance
- billing
- notifications

## Financial pipeline

```text
Transaction Posted
      ↓
    Fan-out
 ┌────┼─────┬──────┐
 ↓    ↓     ↓      ↓
Analytics Health Forecast Insights
                     ↓
                 AI Context
```

Não criar dependência serial desnecessária.

## Retry

Exponential backoff + jitter.
Separar retryable de non-retryable.
DLQ para filas críticas.
Replay controlado e auditado.

## Ordering

Não assumir ordering global.
Usar aggregate version quando necessário.

## ACK

Somente após processamento e commit necessários.

## Backpressure

Monitorar backlog, lag, throughput e tempo de processamento.

## Golden rule

> Consistência primeiro, desacoplamento onde agrega valor, assíncrono onde é seguro.
