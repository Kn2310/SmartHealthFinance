# 05.4 Data Architecture

## Source of Truth

PostgreSQL.

Fatos financeiros persistidos. Dados derivados podem ser reconstruídos. IA nunca é fonte de verdade.

## Persistência

PostgreSQL armazena:
- identity
- workspace
- institutions
- connections
- accounts
- cards
- invoices
- transactions
- installments
- recurring expenses
- categories
- merchants
- goals
- subscriptions/entitlements/usage
- analytics
- health
- forecasts
- insights/evidence
- simulations
- copilot metadata
- audit

Redis:
- cache
- rate limits
- sessões/temporários
- locks
- entitlements cache

RabbitMQ:
- processamento assíncrono

## Multi-tenancy

Workspace como boundary.

Toda entidade financeira possui `workspace_id` direto ou indireto.

Testes de isolamento são obrigatórios.

## IDs

UUID/UUIDv7 quando suportado.

## Naming

snake_case no banco.
Tabelas no plural.

## Tempo

Timestamps em UTC.
Datas de negócio como DATE quando apropriado.

## Dinheiro

`NUMERIC(19,4)` + currency.

Nunca float/double.

Modelo de transação:
- amount positivo
- type: INCOME / EXPENSE / TRANSFER / ADJUSTMENT / REFUND
- status: PENDING / POSTED / CANCELLED / REVERSED

## Deduplicação

external ID quando existir.
Fallback para chave composta adequada.

## Imports

- import_batches
- import_records

Toda importação precisa de rastreabilidade.

## JSONB

Somente para metadados flexíveis. Não substituir modelagem relacional de fatos financeiros consultáveis.

## Integridade

- FK
- constraints simples
- índices por padrão de consulta
- transações DB para comandos multi-entidade
- optimistic locking quando necessário

## Outbox

Transactional Outbox obrigatório para publicação confiável de eventos.

## Migrations

Flyway.

Separar seeds de dados sistêmicos e fake data de desenvolvimento.

## Read models

Analytics, Health, Forecast e Insights são derivados.
